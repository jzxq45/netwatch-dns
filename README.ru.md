# netwatch-dns

> Пассивный DNS-мониторинг, блокировка рекламы и распознавание устройств домашней/офисной сети. Видно, какие домены резолвит каждое устройство, с блокировкой трекеров и определением производителей устройств — без необходимости что-либо ставить на телефоны или ноутбуки.

## Что это делает

- Работает как **DNS-резолвер для всей сети** на одном постоянно включённом хосте (ПК). Роутер раздаёт через DHCP IP этого хоста в качестве DNS, поэтому каждое клиентское устройство присылает ему все свои hostname-запросы.
- Каждый запрос записывается: **IP клиента, домен, тип запроса, время** — в локальный SQLite (WAL-режим).
- Возвращает **NXDOMAIN на известные DoH/DoT-эндпоинты** (`dns.google`, `chrome.cloudflare-dns.com`, …) — *чтобы клиент не мог обойти заданный резолвер* (DNS policy enforcement).
- **Встроенный AdBlock-движок**: поставляется со встроенным [`blocklist.txt`](blocklist.txt) (Google, Yandex, TikTok, Microsoft телеметрия и реклама), поддерживает фоновое автообновление по URL (`blocklist_urls`), белый список (Allowlist) с абсолютным приоритетом и блокировку домена в 1 клик прямо из ленты (🚫).
- **Распознавание устройств (Device Intelligence)**: нативный Win32 `SendARP` резолвит MAC-адреса локальной сети без драйверов (без WinPcap/Npcap), встроенная база вендоров IEEE OUI определяет производителя (Apple, Samsung, Xiaomi, Keenetic и др.), доступно ручное переименование устройств.
- **Производительное DNS-ядро**: регистронезависимый кэш ответов (RFC 1035), защищённый DoH-апстрим (DNS-over-HTTPS), защита от thundering herd (`singleflight`), автопереключение на LAN IP при занятости порта 53 системными службами.
- **Web UI и аудит**: серверный рендер без сборки фронтенда, живая лента на Server-Sent Events (SSE), 24-часовой график активности и угроз, экспорт истории запросов в CSV и JSON (`/api/export`).
- **Интеграция с Windows**: переключение DNS локального ПК в 1 клик, автозапуск через реестр Windows (`HKCU\...\Run`), автонастройка правил Брандмауэра Windows (порты 53 и 8080) и сворачивание в системный трей Windows (`netwatch.exe`).
- **Мобильный компаньон**: прямая раздача готового `netwatch.apk` из веб-панели (`/download/netwatch.apk`) и адаптивная мобильная верстка.
- Retention: строки старше N дней (по умолчанию 7) удаляются раз в сутки.

## Что НЕ делает

- **Нет инспекции TLS/HTTPS.** SNI не читается, содержимое пакетов не просматривается, CA на клиентских устройствах не устанавливается.
- **Нет MITM.** Отклонено принципиально: ломает certificate pinning, требует прав администратора на каждом телефоне.
- **Нет перехвата сырых пакетов.** В этой сборке нет pcap/NetFlow; привилегий выше прав на сокеты не требуется.
- **Не отслеживает HTTP-трафик.** Только DNS-запросы (имена доменов), не какие сайты открыты и сколько времени там провели.
- **Без облака.** Всё остаётся на диске хоста.

## Как это работает

```
 телефон / ноутбук / ТВ      роутер (не меняется, но DHCP выдаёт
      |                      IP хоста-монитора как DNS)
      └─────────────────────────────┐
                                    ▼ UDP/TCP :53
 ┌──────────────────────── монит-хост: monitor.exe ──────────────────────┐
 │                                                                       │
 │  DNS-сервер (udp+tcp :53)                                             │
 │    ├─ кэш RFC 1035 + singleflight дедупликация                        │
 │    ├─ AdBlock / DoH / списки блокировок ──► NXDOMAIN                  │
 │    ├─ лог запроса → async batch writer ──► SQLite (WAL)               │
 │    └─ форвард ──► DoH (https://...) или UDP/TCP 1.1.1.1:53            │
 │                                                                       │
 │  device resolver (Win32 SendARP + база вендоров IEEE OUI)             │
 │  web UI :8080 (SSE живая лента + экспорт CSV/JSON + 24h график)       │
 │  retention sweep (раз в сутки)                                        │
 └───────────────────────────────────────────────────────────────────────┘
```

## Требования

- Хост, работающий в локальной сети: Windows / Linux / Raspberry Pi.
- Права администратора требуются однократно для открытия портов в брандмауэре (на Windows приложение делает это автоматически).
- Роутер с возможностью указать DNS-сервер для DHCP (поддерживается практически всеми роутерами; см. [docs/ROUTER-SETUP.md](docs/ROUTER-SETUP.md)).

## Загрузка и запуск (Windows)

Скачайте релизный архив из раздела [Releases](https://github.com/jzxq45/netwatch-dns/releases/latest). Он содержит:

- **`netwatch.exe`** — десктопное приложение с графическим интерфейсом и сворачиванием в системный трей. При клике на крестик окно прячется в трей, продолжая обслуживать сеть.
- **`monitor.exe`** — консольный сервер для фоновых служб или серверов без графической оболочки.
- **`blocklist.txt`** — готовый стартовый список блокировки трекеров и рекламы.
- **`run.bat`** — скрипт быстрого запуска.
